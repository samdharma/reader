# Reader

A local PDF and Markdown reader. One document per window. The file’s contents decide the format, so a PDF named `notes.md` still opens as a PDF.

This 0.1.0 build is an **unsigned alpha**. It does not auto-update, and it does not send the document anywhere.

## Download and run

Release files are attached to [Reader 0.1.0 alpha](https://github.com/samdharma/reader/releases/tag/v0.1.0). Checksums are in `SHA256SUMS` on that release.

### Windows 11 (64-bit)

1. Download `Reader-windows-x64.exe` from the release.
2. If SmartScreen says Windows protected your PC, click **More info**, then **Run anyway**.
3. Windows 11 includes the WebView2 runtime this build uses. Nothing else to install.
4. Double-click the exe, or in a terminal run `Reader-windows-x64.exe C:\path\to\file.pdf`.
5. Use **Open**, or drop a PDF or Markdown file onto the window. Reader does not ask which format it is.

### Mac

Apple Silicon (M1 or later) is the build to use. An Intel zip is published beside it when that runner succeeds.

1. Download `Reader-macos-arm64.zip` and unzip it. You get `Reader.app`.
2. The first launch is blocked because the app is not notarized. Right-click `Reader.app` and choose **Open**, then **Open** again.
3. If macOS only offers to move it to the Trash, go to **System Settings → Privacy & Security** and click **Open Anyway**.
4. Open a file from the **Open** button, or in Terminal:

   ```sh
   /path/to/Reader.app/Contents/MacOS/reader /path/to/notes.md
   ```

5. Drop a file on the window. Extensions are ignored when the bytes say otherwise.

On an Intel Mac, use `Reader-macos-x64.zip` and the same steps.

## Build from source

You need Rust 1.90+ (stable), Node 22, and pnpm 10.

```sh
pnpm install
cargo test -p reader-core
pnpm test
pnpm tauri dev
```

`pnpm tauri dev` serves the UI at <http://127.0.0.1:1420> and opens the window. Pass a file with:

```sh
pnpm tauri dev -- -- /path/to/document.pdf
```

A release binary:

```sh
pnpm tauri build --no-bundle
```

Icons are generated by that command. On Linux, install WebKitGTK 4.1 first (`libwebkit2gtk-4.1-dev`). The portable Windows exe and the macOS `.app` are produced by GitHub Actions on `windows-latest` and `macos-latest` (see `.github/workflows/release.yml`). This project’s Linux environment cannot cross-compile those binaries. They are unsigned; Authenticode and notarization are later work.

## What this alpha does

- Open by path, File → Open, drag and drop, and on macOS the “Open With” event.
- Sniff the first kilobyte: `%PDF-` means PDF, otherwise text if it looks like text. Corrupt PDFs and unsupported binaries get a specific error, not a format picker.
- PDF: first page through PDF.js range requests, scroll or single page, zoom, fit, rotate, outline, find, text selection, password prompt. JavaScript inside the PDF is not run.
- Markdown: rendered and raw (`Ctrl/⌘ E`), GitHub-flavored tables, tasks, alerts, footnotes, a contents list, find, local images, and Mermaid or KaTeX only when the note actually uses them.
- Light, dark, and system theme. Recent files (up to 10). Remote images stay blocked until you allow them for that file.

Highlight, ink, and free-text annotation are not in this alpha. The core can write a file atomically, and that path is not exposed as a command, so the app cannot be asked to write an arbitrary path.

## Layout

- `crates/reader-core` — sniff, path checks, range reads, settings, the document protocol.
- `src-tauri` — window, menu, CLI, and the `reader://` stream. No filesystem or shell plugin.
- `src` — Preact UI.

Product notes live in `docs/PRD.md`. Measurements that were actually taken are in `docs/SPIKE.md`.
